Tirzepatide Log: architecture

Updated October 2026. The web app and the iPhone app share one log through an invite-only account. Diagram uses the official AWS Architecture Icons.

Download the PNGPlan and decisions (markdown)

What happens when

  • 1 The browser loads the app from tirzepatide.phoe.be: CloudFront in front of a private S3 bucket.
  • 2 Sign in on Cognito's hosted page (PKCE); the app, or the iPhone via its custom scheme, gets a token.
  • 3 Each save, open, pull-down or leaving the app syncs with the API using the token. Last edit per day wins.
  • 4 A doctor opens a link, gets the same app read-only, and the app asks the one public route for that token's data.

Who can do what

  • Only people you invite can have an account; nobody can sign themselves up.
  • The API checks the token and an "allowed" flag on every call and only ever reads that user's rows.
  • A doctor link is read-only, never expires, can be revoked, and stops if its owner's access is removed.
  • The iPhone app cannot import or export files; the account is the only way data moves.

Protections

  • Own browser origin, so no other site can read the app's data.
  • Strict Content-Security-Policy, frame blocking, HSTS, nosniff.
  • Encryption at rest, point-in-time recovery, short log retention that never holds request bodies.
  • Least-privilege Lambda role; an API throttle on every route and a lower one on the public link route.

Not in use yet / to know

  • Stripe payments and Apple in-app purchase: waiting on an account and a decision.
  • The old www.phoe.be/tirzepatide-log/ address only forwards to the new host; GitHub Pages is only a forwarder.
  • Still to do: required MFA, shorter refresh token, privacy policy and delete-account.
  • Infrastructure is Terraform in the private tirzepatide-cloud repo.
